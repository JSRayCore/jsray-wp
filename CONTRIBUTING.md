# Contributing to JSRay WordPress Plugin

Issues and PRs are welcome. This repository is the WordPress integration; changes to
the renderer itself belong in [JSRay Core](https://github.com/JSRayCore/JSRay).

## Development workflow

1. Fork and clone, then symlink or copy the repository into `wp-content/plugins/jsray`
2. Activate **JSRay** in the WordPress admin and exercise the block, the shortcode, and the compatibility path
3. Run the tests: `npm test` (requires Node ≥ 20)
4. Before a release, run `npm run test:compat` — it runs the PHP suite against
   both ends of the range `readme.txt` promises: WordPress 6.0 on PHP 7.4 and
   the current release. A "Requires at least" header nobody tested is a guess
5. Run `npm run check:versions` and `npm run check:core` before opening a PR.
   The second asks npm whether the bundled Core snapshot is still the published
   one — the older drift check compares against a sibling checkout and skips
   when Core is absent, which is every CI run, so a stale engine used to pass a
   green build. It did: a denial of service fixed in Core sat in this bundle
   until somebody measured it.

## Do not edit synced files

This repository **bundles a snapshot** of JSRay Core; it does not depend on Core at runtime.
These files are generated by `tools/sync-core.sh` and will be overwritten:

```text
assets/js/jsray.js
assets/css/jsray.css
assets/css/themes/default.css
```

Fix renderer bugs in Core, then run `sh tools/sync-core.sh` here. Plugin-owned front-end
code lives in `assets/js/jsray-block.js`, `assets/js/jsray-loader.js`, and the
`jsray-block*.css` files.

## WordPress conventions

- Escape on output (`esc_html`, `esc_attr`, `wp_kses_post`) and sanitize on input.
- Guard admin screens with a capability check (`manage_options`).
- Prefix every global function, option, and hook with `jsray_`.
- New extension points should be filters, documented in the README's renderer-boundary section.

## Versioning

The plugin version lives in **three** places and `npm run check:versions` enforces that they agree:
`version.json`, `package.json`, and the `Version:` header in `jsray.php`.
`bundledCore.version` is maintained by the sync script — do not hand-edit it.

## Commit conventions

Short, imperative subjects, optionally scoped:

```
fix(cli): exit quietly when the downstream pipe closes early
feat: add a copy button to the block toolbar
chore: sync Core snapshot (token fallback chain)
docs: correct the language-family count
```

## Pull requests

- One PR per concern, to keep reviews easy.
- Behavior changes must come with added or updated tests — CI runs the suite on Node 18, 20, and 22, and a PR cannot merge red.
- Passing CI is necessary but not sufficient: every PR also needs maintainer review before it merges.
